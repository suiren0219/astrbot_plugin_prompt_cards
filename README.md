# astrbot_plugin_prompt_cards 提示词卡

把多套提示词（System Prompt 片段）存成「卡片」，在每次 LLM 请求前自动拼接到
system prompt。相当于给 AstrBot 人格系统加了一层可切换、可触发的叠加层：

- **按会话切换**：不同群/私聊可以启用不同的卡，互不影响；
- **关键词触发**：卡片绑定触发关键词后，聊天命中即在当前会话自动启用，
  N 条消息后自动失效——世界书式的条件注入，不用每次手动粘贴；
- **可调试**：`/卡 peek` 随时预览当前会话实际注入了什么。

> 定位说明：本插件只做**提示词的管理与注入机制**，卡内容由使用者自行维护
> （人格设定、语气文风、格式要求等常规提示词）。插件本身不内置、也不针对
> 绕过模型安全策略的内容；提示词的实际效果由底层模型决定。

## 安装

1. 把整个 `astrbot_plugin_prompt_cards` 文件夹放进 AstrBot 的 `data/plugins/` 目录；
2. WebUI → 插件管理 → 重载/启用；
3. 需要 AstrBot **v4+**（v4 起人格在 `on_llm_request` 钩子之前组装，卡片注入才能
   正确叠在人格后面；v3.4.x 顺序相反，卡片会被人格覆盖，见 AstrBot #4446）。

`/卡 生成` 抓网页用到 aiohttp（AstrBot 本体已自带，无需额外安装）。

## 命令

前缀 `/` 可省略，子命令与参数之间用空格。

| 命令 | 说明 | 权限 |
| --- | --- | --- |
| `/卡 help` | 查看帮助 | 所有人 |
| `/卡 list` | 列出所有卡片、优先级、关键词、本会话状态 | 所有人 |
| `/卡 show <名字>` | 查看卡片内容 | 所有人 |
| `/卡 peek` | 预览当前会话实际注入的提示词 | 所有人 |
| `/卡 预设` | 查看内置预设库（完全人设/语气风格/回答策略/提示词优化 四类） | 所有人 |
| `/卡 on <名字>` | 在当前会话启用卡片 | 所有人 |
| `/卡 off <名字>` | 在当前会话停用卡片 | 所有人 |
| `/卡 clear` | 停用当前会话的全部卡片 | 所有人 |
| `/卡 add <名字> <内容>` | 新建卡片（内容可换行） | 管理员 |
| `/卡 导入 <预设名>` | 从内置预设库导入一张卡（`导入 全部` 全要） | 管理员 |
| `/卡 生成 [名字] <网址或描述>` | 抓取网页或接收文字，用当前默认 LLM 提炼成结构化角色卡 | 管理员 |
| `/卡 set <名字> <新内容>` | 修改卡片内容 | 管理员 |
| `/卡 kw <名字> <词1,词2>` | 设置触发关键词（`re:` 前缀按正则匹配；留空清除） | 管理员 |
| `/卡 pri <名字> <数字>` | 设置优先级，数字小的先注入 | 管理员 |
| `/卡 全局 on\|off <名字>` | 全局卡：对所有会话默认生效，不必逐群 `/卡 on` | 管理员 |
| `/卡 温度 <名字> <0~2>` | 卡片温度备忘（全局调温在面板「提供商」页），留空清除 | 管理员 |
| `/卡 长度 <名字> <字数>` | 回复字数上限，随卡内容注入提示词引导（软限制），留空清除 | 管理员 |
| `/卡 del <名字>` | 删除卡片 | 管理员 |

管理员判定优先用 `event.is_admin()`，不可用时回退到面板里的 `admin_ids` 名单。

## 快速上手

```
/卡 预设                 ← 看 20 张内置预设：完全人设（大肥鱼、深夜电台DJ…）、语气风格、回答策略、提示词优化
/卡 导入 全部            ← 一键全部入卡，之后 /卡 set 随便改写成你要的样子
/卡 on 文言文腔调        ← 本会话立即生效
/卡 kw 文言文腔调 古风,文言
                        ← 之后聊天里出现「古风/文言」的群会自动启用，30 条消息后自动失效
/卡 peek                ← 看看实际注入了什么
```

预设分四类：**完全人设**（身份/性格/语气/规则/示例台词齐全，导入即用，含按公开形象特征重写的「大肥鱼」）、
**语气风格**（只调口吻）、**回答策略**（只管答案组织）、**提示词优化**（人格锁定、前提先行等元规则，
叠加在其他卡上用）。直接手写 `/卡 add` 也完全可以；写完全人设推荐按「身份→性格（用行为示例
而非形容词）→语气→规则→示例」的结构来，比堆口癖稳定得多。

## 进阶用法

**变量插值**：卡片内容里可以写 `{user}`（发送者昵称）、`{time}`、`{date}`、
`{weekday}`，每次注入时自动替换成当前值。例如预设「时间感知」就是靠它实现的。

**正则关键词**：`/卡 kw 名字 re:(早|晚上)好` —— `re:` 前缀后面按正则匹配，
适合同义表达多、想一条写完的场景；正则写错只影响这一条，不会拖垮插件。

**全局卡**：`/卡 全局 on 简洁模式` 后该卡在所有会话默认生效，不用每个群都
`/卡 on` 一遍；`/卡 全局 off` 恢复手动模式。适合管理员给整个 bot 定基调。

**长对话锚点**：角色扮演聊得越久人格越容易漂，面板开启「长对话锚点」后，
每次请求会在最后一条用户消息前插入一句可自定义的提醒，把人设拉回来。
对话普遍很短（<20 轮）就不用开，省 token。

**发挥度与回复长度分档**（仿角色扮演 App 的三档选择）：

- `/卡 调控 名字 保守|标准|激进`——发挥度：保守=贴紧设定少发挥，标准=跟随卡片
  设定，激进=大胆即兴、主动推动剧情。这是提示词层面的引导，与模型安全策略无关；
- `/卡 长度 名字 简短|适中|冗长`（约 80/200/500 字）或直接填数字——回复长度，
  提示词引导的软限制，不会被砍半截。

同一会话多卡都设了分档时，取优先级最高（数字最小）的那张；留空清除。
WebUI 编辑抽屉里有点按式档位开关。

**AI 生成角色卡**：`/卡 生成 https://zh.moegirl.org.cn/DeepSeek娘`（百科类角色页面）
或 `/卡 生成 一只爱吃白饭、嘴硬心软的鲸鱼娘`——插件抓取网页正文（或直接用你给的文字），
交给 AstrBot 当前配置的默认 LLM，按「身份→性格→语气→规则→示例」结构提炼成卡；
名字由 LLM 起草，想指定就把名字放最前面用空格隔开。抓取仅支持 http/https 公网地址
（内网地址一律拒绝）；动态渲染页可能抓不到正文，遇到提示就复制正文直接发。
生成后先 `/卡 show` 检查再 `/卡 on`，不满意 `/卡 del` 重来。

**注入字数告警**：面板设置 `max_inject_chars` 后，`/卡 peek` 会在生效卡片
总字数超限时警告（只提醒不截断），避免卡片堆太多把上下文挤爆。

## WebUI 控制台

WebUI 唯一入口是 **AstrBot 后台面板页（≥4.24.1）**，随 AstrBot「插件 Pages」机制注册：
打开 AstrBot WebUI（默认 `http://<服务器>:6185/`）→ 插件管理 → 提示词卡 → 打开页面，
鉴权跟随 AstrBot 面板登录，**不需要任何额外端口**——插件不绑端口、不跑自己的服务器
（早期版本自带的 aiohttp 控制台因默认端口 6199 与 aiocqhttp 适配器冲突，v1.5.4 已彻底移除；
实现方式对齐官方文档与社区插件的 Pages 惯例）。

界面为明日方舟：终末地（Endfield）工业风控制台，深浅色跟随 AstrBot 面板：

- **卡片库**：大数字看板 + 编号记录行；点行打开编辑抽屉（内容、关键词、优先级、
  输出长度、发挥度、表达温度、全局/启停），删除需二次确认；
- **会话**：查看各群启用状态与关键词倒计时，单卡停用、整会话清空、**预览实际注入内容**
  （含温度来源与输出长度行）；
- **生成**：贴百科网址或一段描述，AI 提炼为结构化角色卡，检查后保存入库；
- **提供商**：调采样温度（custom_extra_body）与 Gemini 安全阈值（四类拦截挡位，
  「暧昧模式」一键放行骚扰+露骨两类）——写入提供商配置并实时生效（全局）；
- **导出/导入**：卡片与会话状态一键备份为 JSON，支持合并/覆盖导入。

安全：页面经 AstrBot 官方 bridge 转发请求并受面板登录保护，无独立端口暴露；
`/卡 生成` 有 SSRF 防护。界面字体自托管 Saira（OFL 许可，随页面代理分发），
中文回退系统字体。设计语言来自
[endfield-ui-skill](https://github.com/hhikr/endfield-ui-skill)。

## 与 AstrBot 人格的关系（两种模式）

卡片注入在 AstrBot 基础人格 system_prompt 之上（v4 起人格先组装、卡片后注入）。
每张卡有两种**人格适配模式**（`/卡 模式 名字 人设|叠加`，WebUI 也可切换）：

- **叠加（默认）**：卡内容直接拼接，与基础人格和平共处——适合语气、文风、
  格式要求、回答策略这类微调片段；
- **完全人设**：注入时自动加一行优先级声明（“若与更早的人设描述冲突，以本条
  为准”），压过基础人格——适合整体换角色（大肥鱼、深夜电台DJ 这类），
  这样不会出现“既是 AstrBot 默认人格又是猫娘”的身份打架。

## 卡片嵌套引用

卡片内容里可以写 `{{卡:名字}}` 引用另一张卡，注入时递归展开为对方当前内容——
把人格/风格拆成小组件、主卡自由拼装。规则：只取内容（被嵌套卡的发挥度/长度/
人设声明不随之生效）；环形引用、引用已生效卡、引用不存在的卡都保留占位符原样
（`/卡 peek` 与面板预览里肉眼可见）；展开深度上限 5 层。嵌套卡里的 `{user}` 等
变量在展开后照常插值。

## 关于温度（诚实说明）

按请求下发采样参数在插件 API 层面仍不可能（`ProviderRequest` 无
temperature/max_tokens 字段）。但温度可以写在提供商 `custom_extra_body` 里全局生效——
面板「提供商」页现在可以直接调（等价于在提供商配置里填 `{"temperature": 0.9}`），
保存即落盘并热重载，实时生效；Gemini 的安全阈值（暧昧模式的真实开关）也在同一页。
`/卡 温度` 仍是卡片级记录（优先级最高的设定卡说了算），供多套参数备忘。
`/卡 长度` 走提示词引导，真实按卡生效。

## 安全性

- 插件不绑任何端口（无独立服务器）；WebUI 仅经 AstrBot 面板页与官方 bridge，受面板登录保护；
- `/卡 生成` 抓网页仅允许 http/https 公网地址：拒绝内网/回环/链路本地 IP，
  **不自动跟随重定向**（每跳重新校验，防 302 绕过），最多 3 跳、300KB、20 秒超时；
  每一跳固定已验证 IP 连接（防 DNS rebinding）；
- WebUI 卡片内容/生成材料上限 2 万字；页面所有动态内容均转义（无 XSS）；
  字体文件路径做了 basename 防穿越；数据落盘原子写入。

## 已知限制

- 采样温度/Gemini 安全阈值是提供商级全局配置（面板「提供商」页可调，实时生效），
  插件 API 无法按会话下发不同数值；
- 面板页需 AstrBot ≥4.24.1（`register_web_api`）；旧版 AstrBot 无法使用面板页；
- 公网页面若为纯前端渲染（JS 才出内容）抓不到正文，提示后请直接贴文字；
- 每一跳抓取均固定已验证的解析 IP 建立连接，DNS rebinding 时序窗口已消除；
  残余风险限于 DNS 服务器本身被攻破的场景。

## 配置项

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| 卡片之间的拼接分隔符 | `\n\n` | 多张卡片注入时的连接文本 |
| 注入位置 | append | append=在人格提示词后追加；prepend=插在其前 |
| 长对话锚点 | 关 | 超长对话人格漂移时开启；锚点文本可自定义 |
| 注入字数上限告警 | 0 | 生效卡片总字数超过该值时 peek 警告，0=不检查 |
| 关键词自动激活 | 开 | 关闭后关键词不再触发，只能手动 `/卡 on` |
| 关键词卡自动失效条数 | 30 | 关键词激活的卡在 N 条消息后自动停用，0=永不失效 |
| 关键词命中提示 | 关 | 命中时发一条提示，调试触发规则时打开 |
| 仅管理员可增删改 | 开 | 关闭则所有人都能管理卡片 |
| 管理员 ID 备用名单 | 空 | 逗号分隔 |

## 数据

卡片与会话启用状态保存在 AstrBot 插件数据目录：
`data/plugin_data/astrbot_plugin_prompt_cards/cards.json`（路径经
`StarTools.get_data_dir()` 解析，自定义数据目录时自动对准），可直接编辑
（注意 JSON 格式），删除后重启会重新生成两张示例卡。

v1.5.0 及之前版本的数据在 `data/config/astrbot_plugin_prompt_cards.json`，
升级后**首次启动自动迁移**到新位置，旧文件不再使用、可自行删除。

## 常见问题

**开了卡但模型行为没变？**
先 `/卡 peek` 确认内容真的注入了。确认注入后仍无效果，一般是内容写得太弱
或与人格提示词冲突——人格提示词在后（append 模式）优先级更高，可试试把注入
位置改成 prepend。

**关键词总是误触发？**
把关键词写得具体些（用词组而不是单字），或调小失效条数；调试时打开
「关键词命中提示」观察命中情况。

**不同群想用不同人格？**
卡片按会话（群）独立启用，各自 `/卡 on` 需要的卡即可；`/卡 clear` 清空本会话。
